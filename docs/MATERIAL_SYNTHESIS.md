# 現行ゲーム：二つの材料から魔物を生み出す

2026-11-14、ユーザーの「その方向性で一旦今のゲームを完全に修正して」に基づく改修。旧来の身体・攻撃器官・防御器官・培養方式の選択を置き換える。人間界の材料に限定しない。

## 遊びの流れ

1. 配合台で材料を **二つだけ** 選ぶ。投入順は不問。
2. 未発見の配合は材料の立体と生命反応のヒントを表示。完成形・名前・能力は誕生まで伏せる。
3. 製造槽で材料が共鳴し、融合して魔物の姿を形成する。操作ミニゲームはない。演出はスキップ可能。
4. 誕生した魔物を図鑑へ記録。以後は完成形の3Dプレビューと能力を確認できる。
5. 相手に合わせて格納庫の魔物を出撃させ、全自動で戦う。敗北の分析から次の配合を考える。

現段階では素材の消費・収集・品質抽選はない。無効な組み合わせは製造ボタンを無効化し、材料を失わせない。6材料の全組み合わせを生成する仕様ではなく、下記6レシピを個別に造形する。

## レシピと個性

| 材料 | 魔物 | シルエットと固有技 | 最速解禁 |
| --- | --- | --- | --- |
| 鉄くず × 亡霊の灯 | 鉄霊騎士 | 分離した空洞の鎧。葬送の鉄雨で鉄片が集束 | 1日目 |
| 鉄くず × 竜の血 | 熔炉巨人 | 胸に炉を持つ巨体。竜炉砲で貫通砲撃 | 1日目 |
| 古樹の種 × 竜の血 | 焔花竜 | 根の脚と花弁の翼。百花炎走で突進と火柱 | 3日目 |

月光の雫自体は3日目に届くが、相方の星硝子は5日目。造形は Three.js の個別モデル、一覧アイコンは個別SVG。プレイ中に生成AIへ画像生成を要求する仕組みではない。

## 戦闘

- 各魔物の攻撃3回ごとに固有技を自動発動。攻撃力に固有の加算値を加え、敵の防御を貫通する。
- 速度、耐久、装甲、毒、再生、冷気への弱さで相性を作る。現行の火属性2体は冷気に弱く、魔術師は再生を阻害する。
- 演出には固有の身体動作、軌跡・分身・波紋、発光、衝撃波、カメラ、技名表示を使う。効果音は任意でオンにする。
- 一時停止、倍速、結果へのスキップを用意。画面の動きを抑えるOS設定ではカメラの揺れとズームを抑える。
- 計算は描画と独立した決定的なシミュレーション。推奨例は剣士に熔炉巨人、弓兵に焔花竜、魔術師に幽鐘クラゲ。すべての敵に安定勝利する万能種は置かない。

## 物語・進行・保存

序章〜第1章の会話、製造時の掛け合い、相談、目標、敗北分析を配合に合わせて改稿。本社の主人公が仕事を通して限定的な信頼を得る物語は `STORY_TRUST_ARC.md` を維持する。第2章以降の実装は今回の対象外。

保存形式はv3。v2の章進行・個体ID・勝敗履歴を引き継ぎ、旧個体をレシピへ変換する（獣型→焔花竜、毒型→冥樹の番人、火炎型→熔炉巨人、その他→鉄霊騎士）。旧性能の完全再現ではない。最初のv3保存時に元のv2 JSONを `monster-factory/save/v2-backup` に一度だけ残す。発見済みレシピは格納庫から個体が療養棟へ移っても残る。

## 検証

- `npm test`：配合の順序・解禁・無効な配合、戦闘の再現性・固有技・相性、進行・製造の重複防止、保存移行、会話の分岐。
- `npm run build`：型検査と製品ビルド。
- `npm run preview` の起動後に `npm run e2e`：全6体の誕生と固有技、敗北と再配合、全レシピ表示、第1章の迎撃と章末、リロード後の再開。画像の読み込みとブラウザ例外も確認。
- 画面記録は `test/e2e/materials/`。
- `node test/e2e/signatures.mjs`：固有技中の一時停止、再開後の自動決着を1366px幅で検証。
